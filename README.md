# 搜索增强 SearchPlus for Typecho

让 Typecho 的站内搜索**搜得准**，并且**不改核心、不换页面、不脱离主题**。

- 版本：1.0.2
- 环境：Typecho 1.2 / 1.3（本站为 1.3.0）
- 依赖：**无**（可选配合「轻言 Qingyan」插件，装上就顺带列出轻言命中）

---

## 它解决什么问题

Typecho 的搜索把关键词交给两个过滤器（`Widget\Archive::searchHandle()` 里的
`filter('url', 'search')`），于是：

| 现象 | 原因 |
|---|---|
| 搜 `信任 背叛` **0 结果**（明明两个词都有） | `Common::safeUrl()` 第一行就把空格删掉 → 变成 `信任背叛` 这个不存在的词 |
| 搜 `《信任》` 结果被放大（18 篇而不是 2 篇） | `Common::slugName()` 只保留 `[\w_-]`，书名号被丢掉 → 等于搜 `信任` |
| 多词必须**按顺序**出现 | 核心把空格换成 `%`，拼出 `%a%b%` |
| 关键词超过 128 字符被截断 | `slugName()` 的长度上限 |
| 搜 `100%` 之类带通配符的词结果不对 | 核心没有转义 LIKE 的 `%` / `_` |

这些都是 Typecho 的既有行为，社区通行做法是**改核心**（`Archive.php` 里去掉
那两个 `filter(...)`）。本插件不改核心，而是在外围把这些事做对。

## 它怎么做到「不脱离主题」

**页面仍然由核心的 `Archive` + 主题模板渲染** —— 分页、面包屑、文章摘要、样式
全是主题自己的输出。插件只做两件事：

1. 把关键词**编码**成过滤器动不了的词元，放进核心的 `/search/[keywords]/` 路由；
2. 用两个 `Widget_Archive` 钩子把「查什么」换成自己的条件（多词 AND、顺序无关、
   符号不过滤、LIKE 转义）。

```
主题搜索框 (action=/search/)
      │  GET ?s=信任 背叛
      ▼
插件路由 /search            ← 精确路径，与核心的 /search/关键词/ 不冲突
      │  原文 →「过滤器安全编码」→ 302
      ▼
核心路由 /search/信任_20…/   ← 主题模板照常渲染
      │  Widget_Archive 钩子：解码回原文 → 自己查库 → 压栈
      ▼
主题输出文章列表（+ 插件附加的轻言命中）
```

编码规则：`[0-9A-Za-z]` 与（实测能通过过滤器的）中文原样保留，其余每个字节写成
两位十六进制，需要转义时整串加 `sp` 前缀。所以：

- 纯中文 / 纯字母数字的关键词，URL 还是好看的：`/search/信任/`；
- 带空格或符号的变成 `/search/spe4bfa1e4bbbb20e8838ce58f9b/`（可读性一般，但正确）；
- 核心用它拼**分页链接**时也是原样带过去 → 翻到第 2 页不会跑偏；
- 「能不能保留中文」不靠猜：编码时拿核心那两个过滤器**实跑一遍**自检，
  通不过就退化成纯 ASCII，换台服务器也不会坏。

## 安装 / 启用

1. 把 `SearchPlus/` 放进 `usr/plugins/`，在后台「插件」里**启用**；
   **启用后打开它的设置页，最上面就是「怎么用」** —— 里面有可直接抄的两段代码
   （搜索框 action 的判断式写法 + 可选的 `renderExtra()` 调用），
   示例用的就是本主题 GardenWalk 的真实文件，深色后台下也照常显示。

   下面是同样内容的文字版，方便在别处查阅：
2. 主题搜索框的 `action` 指到 `/search/`，并**做一次降级判断**（插件没启用时走原生）：

```php
<?php $gardenSearchAction = class_exists('SearchPlus_Plugin')
    ? rtrim($this->options->siteUrl, '/') . '/search/'
    : $this->options->siteUrl; ?>
<form method="get" action="<?php echo htmlspecialchars($gardenSearchAction, ENT_QUOTES, 'UTF-8'); ?>" role="search">
    <input type="text" name="s" placeholder="搜索文章...">
</form>
```

未启用插件时 `action` 就是站点根 → 原生 `?s=` 搜索，**不会 404**。
（`/search` 这个精确路径与核心的 `/search/关键词/` 不冲突，两个可以并存。）

3. （可选）想在搜索结果页里**附带轻言命中**：把下面这行放进主题的搜索模板
   （本站是 `index.php`，放在文章列表和分页之后）：

```php
<?php if (class_exists('SearchPlus_Plugin')) SearchPlus_Plugin::renderExtra($this); ?>
```

不调用也行：插件注册了 `Widget_Archive:footer` 钩子会兜底（只是位置在页脚附近）。
装了轻言才有那一段；没装轻言/关掉选项时，这个调用什么都不输出。

## 配置项

| 项 | 默认 | 说明 |
|---|---|---|
| 搜索结果页里附带「轻言」命中 | 列出 | 装了轻言时，结果页另列一组轻言命中（松耦合，不装也能工作） |
| 轻言那组最多显示几条 | 5 | 后面跟一个「在轻言里看全部 →」链接 |

## 和轻言（Qingyan）的关系

- **不依赖**：没装轻言就是一个纯粹的「文章精确搜索」插件；
- 装了轻言：结果页会多一组轻言命中（用 `Qingyan_Model::search()/searchCount()/snippet()`），
  「看全部」跳到轻言的前台页 `?q=关键词`（嵌入页与独立页都认这个参数）。

## 已知边界

- 主题搜索框的 `action` 指向插件注册的路由：**停用插件后**它会 404。
  要么按上面的 `class_exists` 写法降级，要么停用后把 `action` 改回站点根。
- 单个关键词限 32 字、最多 6 个词；整串超过 60 字节会被截断（结果页会提示
  「关键词太长，只用了前一部分」）—— 这是 Typecho 关键词 128 字符上限带来的。
- 只搜**文章正文与标题**（不搜附件、不搜评论），只搜 `publish`（作者登录时含自己的私密文章）。

## 文件

```
SearchPlus/
├── Plugin.php        插件入口：启停、路由、钩子、附加内容、配置
├── Engine.php        编码/解码、过滤器自检、查询构造
├── Search.php        /search 跳板 widget（编码后 302 到核心搜索路由）
├── compat.php        Typecho 1.2 / 1.3 类名兼容层
├── assets/search.css 附加内容样式（不依赖主题与其它插件）
└── README.md
```

## 变更

### 1.0.2

- **配置行自愈**：插件被加载/打开设置页时，若 `typecho_options` 里的
  `plugin:SearchPlus` 行**缺失或值为空**，自动补成合法默认值，并且**同一次请求**
  就生效（同时写库与内存里的 Options 副本），设置页不会再报
  「插件SearchPlus的配置信息没有找到」。
  起因：这类「文件拷进去了但没正经启用过」或数据库被回滚过的站点，
  核心设置页会直接取配置行并抛异常（异常在核心里，插件兜不住）；
  而值为空时核心 `configPlugin()` 还会 `array_merge(null, …)` 抛 TypeError，
  导致「禁用→重新启用」也修不好。

### 1.0.1

- **设置页最上面加「怎么用」说明块**：以 GardenWalk 为例给出判断式接线代码
  （搜索框 `action` + 可选的 `renderExtra()`），附验证方法与「升级后若路由没生效就
  停用→启用」的提示。样式走 `--ad-*` 变量，浅色/深色后台都能看。

### 1.0.0

- 首个版本：多词 AND、顺序无关、符号不过滤、LIKE 转义、关键词编码穿过核心过滤器、
  分页保持、标题/面包屑显示原文。
- 可选：结果页附带轻言命中（松耦合）。
